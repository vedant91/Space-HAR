Is all the dataset collected? Synthetic: yes. Real: not yet

The synthetic dataset is fully rendered and passed its quality gate: 23 takes, 22,349 frames, every frame readable. The NASA footage is in. Your own real recordings have not been made yet, and they are the only real-world test of the model.

Is the model trained? Not on the new data

Training has started on the new dataset: the oracle experiment runs first. The model the demo runs today is the old one, which scores 0.170 on unseen performances against a 0.125 chance floor.

Is HMR trained? HMR is not trained by us

HMR is a pretrained 3D body model we would run, not train. It is blocked on two things: a free SMPL registration only you can do, and a C++ compiler. The new render decides whether we need it at all.

Why accuracy has not moved yet

Everything this week went into making the next training run mean something: correcting the data, and removing five separate ways training and the live system saw different inputs. No model has been trained on the corrected pipeline yet, so the 0.201 is still last week's number.

What was wrong, found this week

Each of these would have quietly spoiled training or scoring. All are fixed, and most are now covered by a test.

ProblemEffect
Hands teleported on every step boundaryA one-frame spike marked every label change, so the model could learn the renderer instead of the activity
One scripted motion replayed 23 waysOnly one example of each step existed; the model memorised it
No pitch or yaw in the dataThe half of the rotation space the 2D fix cannot handle had never been tested
The test set would have been emptyThe render plan had no holdout tags, so the headline number could not be computed
A 1-second window for 4–6 second stepsThe model saw a fraction of each action
Live loop at 15–22 fps, training at 30Live windows spanned 4–6 s instead of 3 s
Different pose settings, resolution and threading between training and liveThree more ways the model saw different inputs live than in training
Retrained models never reached the demoThe demo ran the at-chance model whatever was trained
Retrain script pointed at a deleted datasetA bare run would have scored the wrong data and reported it confidently
The finding that matters most

On last week's data, the model scored 0.40 from MediaPipe's noisy pose but only 0.14 from perfect ground-truth pose of the same motion. A model that gets worse with better information is leaning on the pose estimator's quirks, not on what the body is doing. Task T14 tests exactly this on the new data, first.

What happens next, in order

  1. done
    Render finished and gated

    All 23 takes passed: labels consistent, every step present, no teleports, every holdout tag populated, all 22,349 frames readable.

  2. now
    Oracle experiment (T14)

    Train and test on perfect pose, then on MediaPipe pose. Tells us whether the problem is the pose features or the data.

  3. then
    Train on the corrected pipeline and score it

    Held-out accuracy reported separately from training accuracy and error sequences, with the old model re-scored beside it.

  4. then
    Measure 2D on pitch and yaw

    The gate for HMR. If the 2D pipeline holds on out-of-plane attitudes, HMR is optional polish; if it breaks, HMR has a measured job.

  5. then
    Promote the best model into the demo

    Your decision, once real held-out numbers exist.

  6. when you record
    Score on your real takes

    The first number that comes from a human rather than a render.
